# 0.6.86 — TRUE_MPI_XSTAR2XSPEC

## Status

`0.6.86` is a development candidate on top of formally accepted `0.6.85.1`. The accepted local-process `xstar-xspec` path remains available as the reference/oracle. MPI host qualification is required before formal promotion.

## Scope

The new executable is:

```text
xstar-xspec-mpi
```

It introduces MPI only at the XSTAR2XSPEC orchestration layer. It does not change XSTAR scientific arithmetic, controller decisions, native xstinitable grid construction, or xstar2table transforms.

## Build isolation

MPI must remain opt-in.

Normal build:

```bash
make -C src/xstar_tools/xstar/cpp
```

must not invoke `mpic++`, include `mpi.h`, or link MPI libraries.

MPI build:

```bash
make -C src/xstar_tools/xstar/cpp mpi
```

builds `xstar-xspec-mpi` with `MPICXX ?= mpic++`. The direct target is also supported:

```bash
make -C src/xstar_tools/xstar/cpp xstar-xspec-mpi
```

## Execution model

Example:

```bash
mpirun -np 4 xstar-xspec-mpi \
  --input xstinitable.par \
  --data-dir /shared/xstar/data \
  --output-dir /shared/run_mpi
```

Concurrency comes from the MPI communicator size. There is intentionally no `--workers` option in the MPI executable.

The first implementation uses this ownership:

```text
rank 0
  -> create canonical xstinitable.lis / xstinitable.fits

all ranks, including rank 0
  -> claim pending jobs from an MPI-3 RMA counter
  -> run at most one xstar-cpp child at a time
  -> publish only their deterministic loopcontrol job directory

rank 0 after global success
  -> validate every spectrum/STEP/success marker
  -> concatenate STEP strictly by loopcontrol
  -> pass spectra strictly by loopcontrol
  -> invoke xstar-xspec-table
  -> publish four final XSPEC tables
```

This preserves the useful relationship:

```text
mpirun -np N  ~= up to N simultaneous xstar-cpp processes
```

rather than reserving rank 0 as a permanently idle scheduler.

## Dynamic job claiming

All ranks share an MPI-3 one-sided window hosted on rank 0 with two integer fields:

```text
next_pending_slot
failed
```

A rank atomically claims the next pending slot with `MPI_Fetch_and_op(..., MPI_SUM, ...)`. This avoids fixed round-robin load imbalance when XSTAR models take different amounts of time.

The queue index addresses a rank-independent `pending[]` list generated by rank 0. Job identity remains the canonical `loopcontrol`, never the rank number.

## Failure behavior

A failed `xstar-cpp` child sets the distributed failure flag. Other ranks poll that flag while their child process is active. Once failure is observed:

- no new job is claimed;
- active local children are terminated;
- no final XSPEC table publication occurs;
- existing/partial XSTAR products are preserved for inspection;
- failed jobs do not receive `xstar-cpp.success`.

This carries forward the accepted `.85.1` non-destructive failure policy.

## Restart

MPI restart uses the same accepted predicate as local `xstar-xspec`:

```text
xout_spect1.fits
xout_step.log
xstar-cpp.success
```

Rank 0 computes the pending list before MPI distribution. Completed jobs are not placed in the distributed queue.

## Shared-filesystem contract

The first MPI implementation intentionally retains file-backed products as the compatibility boundary. Every rank must therefore see the same paths for:

- the native executables;
- `xstar2xspec-work/` and final output directory;
- atomic data;
- any external spectrum or density files used by the model.

The implementation checks that all ranks can read the generated plan and can create their per-rank logs. A multi-node run without shared paths fails closed.

For atomic data, an explicit shared path is preferred:

```bash
--data-dir /shared/xstar/data
```

rather than relying on launcher-specific environment propagation.

## Deterministic science placement

MPI rank and completion order are orchestration telemetry only. These remain canonical ascending `loopcontrol` operations on rank 0:

- STEP concatenation;
- spectrum list passed to `xstar-xspec-table`;
- PARAMVAL placement;
- final INTPSPEC rows.

## Qualification plan

Local/source gates should establish:

- package/version/docs consistency;
- normal `make` excludes `xstar-xspec-mpi` and MPI compiler use;
- `make mpi` target is present and uses `MPICXX`;
- MPI source contains the rank-independent loopcontrol gather contract;
- accepted `.85.1` standalone/science/planner/table sources remain unchanged except version/docs where intended;
- source compiles with a strict MPI API surface when a real MPI toolchain is unavailable locally.

Real-host MPI promotion should then require an actual MPI implementation and runtime, for example:

```bash
make -C src/xstar_tools/xstar/cpp mpi
mpirun -np 2 src/xstar_tools/xstar/cpp/xstar-xspec-mpi ...
```

Recommended host closure:

1. `-np 1` versus accepted local `xstar-xspec --workers 1`;
2. `-np 2` four-job smoke;
3. restart with 4/4 reuse;
4. final four tables bit-exact to the corresponding accepted local run;
5. canonical STEP equality;
6. injected one-rank failure proving no final-table publication and retained forensic products.

No broad/multi-element science rerun is required merely to qualify orchestration unless a scientific source is reopened.
