# Layered CI and release engineering

Milestone 10 keeps the accepted scientific freeze separate from routine software
quality checks. The canonical all-62 suite is **not** a pull-request prerequisite.

## Tier 0 — every pull request

`.github/workflows/ci-tier0.yml` is self-contained on GitHub-hosted runners and
checks:

- Python syntax and stable imports;
- a public API annotation/type contract;
- fatal Python lint errors plus the repository text-format policy;
- the active pytest suite on Python 3.9, 3.11, and 3.13;
- a complete C++ `make` build with the release warning flags;
- package-version metadata;
- no committed build/cache products;
- C ABI/header consistency (`60487`, production-zone ABI `6048110`);
- the complete parity-freeze manifest/checker boundary.

Tier 0 never launches the 62-model benchmark suite.

The source-faithful scientific tree is deliberately not mass-reformatted. The
format policy is therefore conservative: UTF-8/LF/final-newline/trailing-space
rules are enforced on public/product/CI files, while Ruff is used for fatal
Python defects. Scientific source formatting changes remain explicit refactors.

## Science runner assets

Tiers 1–3 use a labeled self-hosted runner:

```text
[self-hosted, linux, x64, xstar-science]
```

The runner should provide these canonical assets, either at the default paths
or through inherited runner-service environment variables:

| Environment variable | Default |
|---|---|
| `XSTAR_TOOLS_CI_SUITE_ARCHIVE` | `/opt/xstar-ci/original_xstar_benchmark_run.tar.gz` |
| `XSTAR_TOOLS_CI_DATA_DIR` | `/opt/xstar-ci/data` |
| `XSTAR_TOOLS_CI_FORTRAN_REFERENCE` | `/opt/xstar-ci/original_xstar.tar.gz` |
| `XSTAR_TOOLS_CI_CPP44_REFERENCE` | `/opt/xstar-ci/v064812344_all62_three_mode.tar.gz` |

`tools/ci/require_science_assets.py` fails closed when required assets are
missing. Pull requests from forks never execute arbitrary code on the self-hosted
science runner.

## Tier 1 — selected scientific smoke

`.github/workflows/ci-tier1-science-smoke.yml` runs only when scientific or
orchestration paths change (plus merge/manual execution). The default cases are:

```text
helike_type69/o7_ne1e10
helike_type69/mg11_ne1e8
helike_type69/ca19_xi2_ne1
```

They run in `pure-python` and `zone-python`. C5 is deliberately absent from the
default set; a manual dispatch can opt into one frozen C5 diagnostic case.

The gate requires:

- canonical Fortran material numerical acceptance;
- FITS publication membership diagnostics under the frozen structural policy;
- STEP numerical/comparator acceptance;
- complete Python-run provenance, including science revision, zone ABI, and
  atomic-data hashes.

## Tier 2 — selected backend parity

`.github/workflows/ci-tier2-backend-parity.yml` runs on merge, nightly, manual
dispatch, or a same-repository pull request carrying the `science-affecting`
label. The same O/Mg/Ca cases are exercised across all five public modes:

```text
pure-python
zone-python
zone-cpp
zone-all
xstar-cpp
```

Each mode must remain scientifically accepted against canonical Fortran. The
three current C++ modes must additionally remain exact against frozen C++
`0.6.48.12.3.44`. Current backend pairs are compared directly on material
numerical science and STEP numerical science; publication inventory remains a
diagnostic between Python/C++ modes rather than being silently converted into a
numerical tolerance.

## Tier 3 — all-62

`.github/workflows/ci-tier3-all62.yml` is restricted to nightly, manual, and
release-candidate tag execution. It runs all 62 models in the three full C++
modes and keeps only the selected O/Mg/Ca subset for the slower Python modes.

The release report is generated by `tools/ci/report_benchmark_results.py` and
contains both per-model and grouped tables. Group dimensions are:

- element;
- density regime;
- ionization regime;
- backend;
- runtime.

A single global runtime average is explicitly **not** a release gate.

## Packaging CI

Packaging remains independent from scientific benchmark tiers. The packaging
workflow has separate jobs for:

- source distribution;
- Python-only wheel;
- clean wheel installation without a source checkout;
- editable installation;
- native Linux wheels;
- Python-only macOS/Windows wheels.

Conda and documentation remain separate workflows (`conda.yml` and `docs.yml`),
with the conda recipe build/test and Sphinx warnings-as-errors/linkcheck kept as
independent release surfaces.

## Performance CI

`.github/workflows/performance.yml` requires a separately labeled controlled
runner:

```text
[self-hosted, linux, x64, xstar-perf]
```

It writes a performance-only JSON series. Performance regressions are reported
separately and do not alter scientific acceptance. Conversely, science
acceptance does not erase a performance regression.

## Evidence and helper tools

CI logic is kept in testable repository scripts rather than opaque workflow
shell fragments:

- `check_tree_clean.py` — generated-artifact policy;
- `check_python_contract.py` — syntax/import/public API type contract;
- `check_text_policy.py` — conservative format policy;
- `check_package_metadata.py` — distribution/ABI/header consistency;
- `require_science_assets.py` — canonical self-hosted asset resolution;
- `check_science_results.py` — material/publication/provenance/STEP gate;
- `report_benchmark_results.py` — Tier-3 physical-regime report;
- `performance_report.py` — performance-only evidence.

The Milestone-10 qualification manifest/checker pins these contracts without
changing the accepted science revision.
