\section{Overview}

\texttt{xstar-atomic} is a Python package for reading, decoding, and evaluating atomic data from XSTAR's packed atomic database file, usually named \texttt{atdb.fits} and distributed under \texttt{xstar/data/atdb.fits}.

The package is intended for research workflows that need direct access to XSTAR atomic records, line lists, rate coefficients, emissivity tables, and prototype level-population calculations. It is separate from \texttt{PyXSTARdb}/\texttt{PyXstar}: \texttt{xstar-atomic} focuses on direct decoding and physics evaluation of the released packed FITS database.

\section{Database structure}

The public XSTAR \texttt{atdb.fits} file is not a normal multi-table atomic database. It contains four packed arrays:

\begin{lstlisting}[style=ctterminal]
POINTERS
REALS
INTEGERS
CHARS
\end{lstlisting}

Each physical database record is reconstructed from these arrays. The package rebuilds the XSTAR hierarchy:

\begin{lstlisting}[style=ctterminal]
element -> ion -> levels -> radiative/collisional/photoionization/recombination records
\end{lstlisting}

The low-level reader is \texttt{ATDB}. The high-level user interface is \texttt{XSTARAtomic}.

\section{Current capabilities}

The package currently includes:

\begin{itemize}
\item Packed FITS decoding of \texttt{POINTERS}, \texttt{REALS}, \texttt{INTEGERS}, and \texttt{CHARS}.
\item Element, ion, and record indexing.
\item Level extraction for \texttt{data\_type=6}.
\item Radiative-line extraction for \texttt{data\_type=50}.
\item Photoionization extraction for \texttt{data\_type=53} and inventory support for related bound-free records.
\item Collisional excitation extraction/evaluation for \texttt{data\_type=51}, \texttt{56}, \texttt{63}, and \texttt{98}, including the implemented same-\(n\) \(l\)-mixing branch of the Bautista/XSTAR algorithm for \texttt{data\_type=63}.
\item Recombination and charge-exchange inventory/evaluation for \texttt{data\_type=1}, \texttt{30}, \texttt{38}, \texttt{39}, and charge exchange \texttt{data\_type=2} when explicitly requested.
\item Direct-excitation line-emissivity table generation.
\item CSV/HDF5 export bundles for plasma post-processing workflows.
\item Line-based X-ray band emissivity exports via \texttt{--bands-kev}.
\item Prototype level-population solver with connected-component diagnostics and source/sink hooks.
\item Prototype radiative-branching cascade redistribution for source-injection experiments.
\end{itemize}

\section{Important limitations}

This is an alpha-stage research package. Important limitations include:

\begin{itemize}
\item Not all XSTAR data types are decoded.
\item The \texttt{data\_type=63} same-\(n\) \(l\)-mixing / XSTAR \texttt{amcrs} branch is implemented in the collision decoder, but should still be compared against XSTAR outputs for final science.
\item True level-resolved recombination/cascade records have not been identified in the currently decoded oxygen records.
\item Recombination source redistribution modes are prototypes unless true level-resolved recombination data are available.
\item The level-population solver is a diagnostic prototype, not a full replacement for XSTAR.
\item Results should be validated against XSTAR outputs, published atomic values, or other atomic databases before scientific publication.
\end{itemize}

\section{Python API}

\subsection{Open the database}

\begin{lstlisting}[style=ctpython]
from xstar_atomic import XSTARAtomic, ATDB

db = XSTARAtomic("/path/to/xstar/data/atdb.fits")
\end{lstlisting}

\subsection{Low-level database index}

\begin{lstlisting}[style=ctpython]
from xstar_atomic import ATDB

atdb = ATDB("/path/to/xstar/data/atdb.fits")
records, elements, ions = atdb.build_index()
print(len(records), len(elements), len(ions))
\end{lstlisting}

For the tested XSTAR database this returns approximately:

\begin{lstlisting}[style=ctterminal]
1216792 30 465
\end{lstlisting}

\subsection{Extract O VIII Ly-alpha lines}

\begin{lstlisting}[style=ctpython]
from xstar_atomic import XSTARAtomic

db = XSTARAtomic("/path/to/xstar/data/atdb.fits")
lines = db.lines("O VIII", wavelength=(18.8, 19.1), slim=True)

for line in lines:
    print(line["wavelength_A"], line["lower_label"], "->", line["upper_label"])
\end{lstlisting}

The following ion names are accepted as equivalent:

\begin{lstlisting}[style=ctpython]
db.lines("O VIII")
db.lines("o viii")
db.lines("o_viii")
db.lines("O-VIII")
db.lines("OVIII")
db.lines("o8")
\end{lstlisting}

\subsection{Evaluate collisional excitation rates}

\begin{lstlisting}[style=ctpython]
coll = db.collisions(
    "O VIII",
    lower_level=1,
    wavelength=(18.8, 19.1),
    temperatures=[1e6, 3e6, 1e7],
)

print(coll.keys())
print(len(coll["summary"]), len(coll["evaluated"]))
\end{lstlisting}

The evaluated rows include \texttt{upsilon}, \texttt{q\_excitation\_cm3\_s}, \texttt{q\_deexcitation\_cm3\_s}, and \texttt{eval\_method}.

\subsection{Recombination inventory}

\begin{lstlisting}[style=ctpython]
recomb = db.recombination(element="O", temperatures=[1e6])
print(len(recomb["records"]))
print(len(recomb["evaluated"]))
\end{lstlisting}

Electron recombination and charge exchange are separated by \texttt{source\_kind}.

\subsection{Build an O VIII Ly-alpha emissivity table}

\begin{lstlisting}[style=ctpython]
emiss = db.emissivity(
    "O VIII",
    wavelength=(18.8, 19.1),
    temperatures=[1e6, 3e6, 1e7],
)

print(emiss["summary"])
print(emiss["emissivity"][0])
\end{lstlisting}

The direct-excitation emissivity coefficients are approximately:

\begin{align}
\epsilon_{\rm ph}(T) &= q_{ij}(T) B_{ul}, \\
\epsilon_{\rm E}(T) &= q_{ij}(T) B_{ul} h\nu,
\end{align}

where \(B_{ul}\) is the radiative branching ratio. These coefficients are per \(n_e n_{\rm ion}\).

\subsection{Prototype solver}

\begin{lstlisting}[style=ctterminal]
xstar-atomic-solver /path/to/atdb.fits \
  --element O --ion-stage 8 \
  --wavelength-min 18.8 --wavelength-max 19.1 \
  --temperatures 1e6 3e6 1e7 \
  --electron-densities 1.0 \
  --electron-density-for-lmixing 1.0 \
  --component-mode ground \
  --linear-solver sparse \
  --out-lines-csv o8_lya_pop_lines.csv \
  --print-summary
\end{lstlisting}

Use \texttt{--linear-solver dense}, \texttt{--linear-solver sparse}, or \texttt{--linear-solver auto}. The sparse solver uses \texttt{scipy.sparse.linalg.spsolve} when SciPy is available and falls back to dense least-squares if needed.


\subsection{Plasma export bundles}

\begin{lstlisting}[style=ctterminal]
xstar-atomic-export /path/to/atdb.fits \
  --ions "O VIII,Ne IX" \
  --temperatures 1e6 3e6 1e7 \
  --wavelength-min 1.0 --wavelength-max 40.0 \
  --formats csv,hdf5 \
  --out-dir atomic_export \
  --print-summary
\end{lstlisting}

This writes per-ion CSV products, optional HDF5 tables, and JSON manifests. The export is intended for superwind, AGN outflow, and other plasma post-processing workflows.

\subsection{X-ray band emissivity exports}

Line-by-line emissivity tables are useful for detailed diagnostics, but post-processing of simulated outflows often needs integrated X-ray bands. The export command supports line-based band sums with \texttt{--bands-kev}, using band specifications of the form \texttt{name:emin:emax} in keV.

\begin{lstlisting}[style=ctterminal]
PYTHONPATH=src python -m xstar_atomic.export /path/to/atdb.fits \
  --ions "O VIII,Ne IX" \
  --temperatures 1e6 3e6 1e7 \
  --wavelength-min 1.0 \
  --wavelength-max 40.0 \
  --bands-kev soft:0.5:2.0 osoft:0.3:0.6 med:0.6:1.0 hard:2.0:10.0 \
  --formats csv,hdf5 \
  --out-dir atomic_export \
  --print-summary
\end{lstlisting}

For each ion this writes:

\begin{lstlisting}[style=ctterminal]
<ion>_band_emissivity.csv
<ion>_atomic.h5:/band_emissivity
\end{lstlisting}

The band-emissivity table contains:

\begin{lstlisting}[style=ctterminal]
ion
band_name
energy_min_keV
energy_max_keV
temperature_K
n_lines_in_band
energy_emissivity_coeff_erg_cm3_s
photon_emissivity_coeff_cm3_s
methods_used
\end{lstlisting}

The coefficients are local line-emissivity coefficients per \(n_e n_{\rm ion}\), summed over the selected lines in each band. They are not full plasma cooling functions unless combined with ion fractions and abundances. Zero-line bands are retained with \texttt{n\_lines\_in\_band=0}, \texttt{methods\_used="none"}, and the ion label filled.

A validated Stage-4 test used four bands and three temperatures for O VIII and Ne IX, giving
\[
4\ {\rm bands}\times 3\ {\rm temperatures}=12
\]
band-emissivity rows per ion. The real-ATDB validation confirmed that CSV and HDF5 products contain \texttt{/band\_emissivity}, that all zero-line bands keep the ion label, and that no \texttt{methods\_used} entries are blank.

Recommended near-term development priorities are:

\begin{enumerate}
\item Complete missing rate decoders, especially collision \texttt{data\_type=51}, \texttt{98}, and the same-\(n\) branch of \texttt{data\_type=63}.

\section{Collision Decoder Coverage}

The collision module evaluates the following XSTAR ATDB collision paths:

\begin{center}
\begin{tabular}{rll}
\hline
Data type & Meaning & Status\\
\hline
51 & Burgess--Tully scaled OP/CHIANTI collision strengths & evaluated\\
56 & Tabulated effective collision strengths & evaluated\\
63 & Bautista algorithmic $n,l$ collisions & evaluated\\
98 & CHIANTI-2016-style Burgess--Tully collision strengths & evaluated\\
\hline
\end{tabular}
\end{center}

For data type 63, both the $n_f \neq n_i$, $|\Delta l|=1$ branch and the same-$n$ $l$-mixing branch are evaluated. The same-$n$ branch follows the XSTAR \texttt{amcrs}/\texttt{velimp} ecm=0 logic and depends weakly on electron density through the impact-parameter cutoff.


\section{Collision-Decoder Validation}

The package includes validation helpers for the collision-rate decoders that are
most important for the next development stage: data types 51, 98, and the
same-$n$ branch of data type 63.  The validation command can inventory ions,
find representative records with positive evaluated rate coefficients, and run
an O~VIII type-63 same-$n$ l-mixing regression diagnostic.

\begin{verbatim}
PYTHONPATH=src python -m xstar_atomic.validation atdb.fits \
  --inventory --find-targets --data-types 51 98

PYTHONPATH=src python -m xstar_atomic.validation atdb.fits \
  --type63-same-n --element O --ion-stage 8 \
  --temperatures 1e6 --electron-density 1.0
\end{verbatim}

The type-63 same-$n$ diagnostic checks the Python port of the XSTAR
\texttt{amcrs/velimp} branch.  It is a regression diagnostic, not a substitute
for comparison against XSTAR model outputs.

\section{Stage-3 sparse level-population solver diagnostics}

The level-population solver supports the XSTAR type-63 same-\(n\) \(l\)-mixing
collision decoder and can solve the statistical-equilibrium matrix with either a
dense or sparse backend.

\begin{lstlisting}[style=ctterminal]
PYTHONPATH=src python -m xstar_atomic.solver ../xstar/data/atdb.fits \
  --element O \
  --ion-stage 8 \
  --wavelength-min 18.8 \
  --wavelength-max 19.1 \
  --temperatures 1e6 \
  --electron-densities 1.0 \
  --electron-density-for-lmixing 1.0 \
  --component-mode ground \
  --linear-solver sparse \
  --summary-json o8_sparse_solver_summary.json \
  --print-summary
\end{lstlisting}

The solver summary reports matrix nonzero counts, matrix density, singular-value
rank estimates, condition numbers, residual norms, sparse availability, and
whether sparse solving was actually used.  The optional
\texttt{--prune-unconnected-levels} flag removes isolated levels before the
solve while preserving the ground level, output-line levels, and explicit
source/sink levels.

For an O VII triplet stress test, run:

\begin{lstlisting}[style=ctterminal]
PYTHONPATH=src python examples/10_o7_triplet_sparse_solver.py \
  ../xstar/data/atdb.fits \
  --out-dir o7_triplet_solver_example
\end{lstlisting}

The O VII diagnostic table includes prototype \(R=f/i\) and
\(G=(f+i)/r\) ratios.  These ratios are useful for solver debugging, but they
are not final physical predictions unless the recombination/cascade source model
is physically complete.

\subsection{Notes on a future C++ backend}

The current sparse solve uses SciPy's compiled sparse linear-algebra routines,
so the linear solve itself is already handled by optimized native code when
\texttt{--linear-solver sparse} is available.  A C++ backend could still improve
performance for repeated production workflows by moving repeated ATDB filtering,
rate-evaluation loops, sparse matrix assembly, emissivity aggregation, and HDF5
packing out of pure Python.  The recommended design is an optional backend, for
example through \texttt{pybind11} or a small C ABI extension, while keeping the
pure Python/SciPy implementation as the portable reference path.



\section{Solver Step Profiling and Stage-6 Cascade Workflow}

The solver profiler separates the wall-clock time spent in the main execution
stages:

\begin{lstlisting}[style=ctterminal]
PYTHONPATH=src python examples/12_profile_solver_steps.py \
  ../xstar/data/atdb.fits \
  --element O --ion-stage 8 \
  --wavelength-min 18.8 --wavelength-max 19.1 \
  --temperature 1e6 --electron-density 1.0 \
  --linear-solver sparse \
  --out-dir solver_profile_example
\end{lstlisting}

The timing output reports \texttt{open\_read\_atdb}, \texttt{build\_index},
\texttt{extract\_levels}, \texttt{extract\_lines},
\texttt{extract\_collisions}, \texttt{evaluate\_collisions},
\texttt{build\_matrix}, \texttt{solve\_matrix}, \texttt{write\_outputs}, and
\texttt{total}.  These timings are intended to identify whether future
optimization should target record filtering, rate evaluation, matrix assembly,
or output generation.

A future C++ accelerator backend can be implemented as an optional shared-object
library (\texttt{.so} on Linux) loaded from Python through \texttt{pybind11},
\texttt{cffi}, or \texttt{ctypes}.  The Python/SciPy backend remains the
reference path.  The most useful first C++ targets are ATDB record filtering,
record payload unpacking, collision-rate loops, sparse matrix assembly,
emissivity aggregation, and HDF5 packing.  The sparse linear solve itself is
already handled by compiled SciPy backends when SciPy is available.

The prototype Stage-6 O~VII recombination/cascade workflow can be run with:

\begin{lstlisting}[style=ctterminal]
PYTHONPATH=src python examples/13_o7_recombination_cascade_workflow.py \
  ../xstar/data/atdb.fits \
  --out-dir o7_recomb_cascade_workflow \
  --xstar-lines-csv xstar_test_run/xstar_o7_triplet_lines.csv \
  --print-summary
\end{lstlisting}

This workflow evaluates total O~VIII $\rightarrow$ O~VII recombination,
distributes the source over selected O~VII levels, applies an approximate
radiative-branching cascade redistribution, feeds the resulting source CSV into
the sparse solver, and writes prototype triplet diagnostics
$R=f/i$ and $G=(f+i)/r$.  It is useful for source-interface and sensitivity
tests, but it is not yet a final level-resolved recombination/cascade model.



\section{Recommended Array-backed NPZ Index Cache}

The ATDB hierarchy scan is often the dominant startup cost because it walks
more than one million packed records.  For repeated targeted workflows, use the
array-backed NumPy/NPZ cache.  This cache stores the hierarchy as numeric arrays,
filters by element, ion stage, data type, and rate type, and converts only the
selected rows to \texttt{IndexedRecord} objects.

\begin{lstlisting}[style=ctterminal]
PYTHONPATH=src python examples/12_profile_solver_steps.py \
  ../xstar/data/atdb.fits \
  --element O --ion-stage 8 \
  --wavelength-min 18.8 --wavelength-max 19.1 \
  --temperature 1e6 --electron-density 1.0 \
  --linear-solver sparse \
  --index-cache \
  --index-cache-format npz \
  --out-dir solver_profile_npz_arrays_hit
\end{lstlisting}

For the validated O~VIII sparse-solver profile, the uncached run took about
\texttt{5.31 s}, while the NPZ array-backed cache-hit run took about
\texttt{0.53 s}.  The \texttt{build\_index} stage dropped from about
\texttt{5.00 s} to about \texttt{0.058 s}.

The default cache file is
\texttt{atdb.fits.xstar\_atomic\_index.npz}.  Use
\texttt{--rebuild-index-cache} after changing or replacing \texttt{atdb.fits}.
Legacy pickle caching remains available with
\texttt{--index-cache-format pickle}, but the NPZ array-backed cache is the
recommended path for solver, export, high-level API, and profiling workflows.

The same cache should be used for repeated export workflows:

\begin{lstlisting}[style=ctterminal]
PYTHONPATH=src python -m xstar_atomic.export ../xstar/data/atdb.fits \
  --ions "O VIII,Ne IX" \
  --temperatures 1e6 3e6 1e7 \
  --wavelength-min 1.0 --wavelength-max 40.0 \
  --bands-kev soft:0.5:2.0 med:0.6:1.0 hard:2.0:10.0 \
  --formats csv,hdf5 \
  --index-cache --index-cache-format npz \
  --out-dir atomic_export_cached \
  --print-summary
\end{lstlisting}

Solver and export summaries report \texttt{index\_cache\_status} and
\texttt{index\_cache\_path}; cache-hit workflows should report statuses such
as \texttt{npz\_array\_hit} or \texttt{array\_memory}.


\subsection{Stage 6 cascade-yield source allocation}

The O VII recombination/cascade workflow supports a prototype
\texttt{selected-cascade-yield} source distribution for total O VIII $\rightarrow$
O VII recombination.  Candidate source levels are weighted by their
radiative-cascade probability of feeding selected target levels, such as the
O VII triplet upper levels.  This is still approximate because the decoded
oxygen recombination records are total rates, not true level-resolved
recombination feeds.

\begin{lstlisting}[style=ctterminal]
PYTHONPATH=src python examples/13_o7_recombination_cascade_workflow.py \
  ../xstar/data/atdb.fits \
  --source-mode selected-cascade-yield \
  --cascade-target-levels 2:1.0,3:1.0,4:1.0,5:1.0,7:1.0 \
  --cascade-weight-floor 0.02 \
  --out-dir o7_recomb_cascade_workflow \
  --xstar-lines-csv xstar_test_run/xstar_o7_triplet_lines.csv \
  --print-summary
\end{lstlisting}




\subsection{Stage-6 O VII triplet target maps}

The recommended Stage-6 baseline is the equal-target map:

\begin{lstlisting}[style=ctterminal]
--source-mode selected-cascade-yield \
--cascade-target-levels 2:1.0,3:1.0,4:1.0,5:1.0,7:1.0
\end{lstlisting}

This preserves the good \(G=(f+i)/r\) agreement with the XSTAR O VII reference. The experimental preset

\begin{lstlisting}[style=ctterminal]
--cascade-target-preset o7-triplet-f2i025-rkeep
\end{lstlisting}

expands to \texttt{2:0.75,3:1.0833333333,4:1.0833333333,5:1.0833333333,7:1.0}. It shifts weight from the forbidden target into the intercombination targets while preserving the resonance target and approximately preserving the total triplet-target weight. Manual \texttt{--cascade-target-levels} overrides any preset.

\section{Data download and path configuration}

\texttt{xstar-atomic} does not bundle the large XSTAR \texttt{atdb.fits} file. Use the interactive helper to download it or to save the path to an existing local copy:

\begin{lstlisting}[style=ctterminal]
python -m xstar_atomic.data
# or, after installation
xstar-atomic-download-data
\end{lstlisting}

The helper reports the remote file size, asks whether to download, asks for a destination directory, downloads with a single-line ASCII progress bar, and stores the selected data directory in \texttt{datapath}. In a source checkout, the default destination is the project-level \texttt{data/} directory and the persistent path file is the project-level \texttt{datapath}.

\begin{lstlisting}[style=ctterminal]
xstar data: downloading atdb.fits [#####-----------------------]  20% (166.5 MB/830.7 MB)
\end{lstlisting}

The default public source is:

\begin{lstlisting}[style=ctterminal]
https://heasarc.gsfc.nasa.gov/FTP/software/lheasoft/lheasoft6.36/heasoft-6.36/ftools/xstar/data/atdb.fits
\end{lstlisting}

Configure an existing file non-interactively:

\begin{lstlisting}[style=ctterminal]
python -m xstar_atomic.data --set-path /path/to/atdb.fits
python -m xstar_atomic.data --show
\end{lstlisting}

Top-level Python helpers are available:

\begin{lstlisting}[style=ctpython]
from xstar_atomic import (
    download_data,
    resolve_atdb_path,
    find_atdb_file,
    get_data_path,
    set_data_path,
)

path = download_data()
set_data_path("/path/to/xstar/data/atdb.fits")
path = resolve_atdb_path()
\end{lstlisting}

After configuration, the high-level API can omit the FITS path:

\begin{lstlisting}[style=ctpython]
from xstar_atomic import XSTARAtomic

db = XSTARAtomic(index_cache=True, index_cache_format="npz")
lines = db.lines("O VIII", wavelength=(18.8, 19.1), slim=True)
\end{lstlisting}

Path resolution order is explicit path, \texttt{XSTAR\_ATDB\_FITS}, \texttt{datapath}, \texttt{data/atdb.fits}, then interactive download/configuration.


\subsection{Stage-6 O VII cascade tuning scan}

The equal-target \texttt{selected-cascade-yield} map remains the recommended Stage-6 baseline because it preserves the good XSTAR agreement in \(G=(f+i)/r\):

\begin{lstlisting}[style=ctterminal]
--source-mode selected-cascade-yield \
--cascade-target-levels 2:1.0,3:1.0,4:1.0,5:1.0,7:1.0
\end{lstlisting}

For controlled experiments, the preferred presets shift target weight from the forbidden upper level into the intercombination upper levels while preserving the resonance target and the total triplet-target weight. This is intended to reduce \(R=f/i\) without strongly moving \(G=(f+i)/r\) away from the equal-target baseline:

\begin{lstlisting}[style=ctterminal]
o7-triplet-f2i010-rkeep -> 2:0.90,3:1.0333333333,4:1.0333333333,5:1.0333333333,7:1.0
o7-triplet-f2i015-rkeep -> 2:0.85,3:1.05,4:1.05,5:1.05,7:1.0
o7-triplet-f2i025-rkeep -> 2:0.75,3:1.0833333333,4:1.0833333333,5:1.0833333333,7:1.0
o7-triplet-f2i050-rkeep -> 2:0.50,3:1.1666666667,4:1.1666666667,5:1.1666666667,7:1.0
\end{lstlisting}

The older simple \texttt{fdown} presets remain available for reproducibility, but they reduced \(G\) too much in the first tuning scan.

Use the tuning scan helper to run the equal baseline plus the experimental presets and summarize \(R=f/i\) and \(G=(f+i)/r\) relative to the saved XSTAR O VII reference:

\begin{lstlisting}[style=ctterminal]
PYTHONPATH=src python examples/15_o7_cascade_tuning_scan.py \
  ../xstar/data/atdb.fits \
  --out-dir o7_cascade_tuning_scan \
  --xstar-lines-csv xstar_test_run/xstar_o7_triplet_lines.csv \
  --print-summary
\end{lstlisting}

The scan writes \texttt{o7\_cascade\_tuning\_scan.csv} and a JSON summary. The aim is to reduce \(R\) while keeping \(G\) close to the equal-target/XSTAR value; the equal map remains the baseline unless an experimental preset improves both.



\subsection{Type-68-aware O VII cascade tuning scan}

After He-like collision data types 67, 68, and 69 are enabled, O VII includes metastable-to-intercombination coupling from level 2 into levels 3, 4, and 5.  This gives the expected density-sensitive behavior in \(R=f/i\), but it can make the low-density \(G=(f+i)/r\) too small for the previous cascade-source map.  The type-68-aware scan keeps the equal triplet weights fixed and progressively downweights the resonance target level 7:

o7-triplet-type68-r075 -> 2:1.0,3:1.0,4:1.0,5:1.0,7:0.75
o7-triplet-type68-r070 -> 2:1.0,3:1.0,4:1.0,5:1.0,7:0.70

The equal target map remains the reference baseline; the type-68-aware presets are experiments for restoring \(G\) while preserving the density-sensitive \(R\) physics.


\section{Stage-6 O VII metastable/intercombination coupling diagnostic}

The O VII triplet ratio \(R=f/i\) is sensitive to transfer from the
forbidden-line upper level into the intercombination manifold.  The example
\texttt{examples/16\_o7\_metastable\_coupling\_diagnostics.py} inspects level
2 to levels 3, 4, and 5 and compares \(C_{2j}=n_e q_{2j}\) against decoded
radiative rates.

\begin{lstlisting}[style=ctterminal]
PYTHONPATH=src python examples/16_o7_metastable_coupling_diagnostics.py \
  ../xstar/data/atdb.fits \
  --temperature 1e6 \
  --electron-densities 1 1e4 1e8 1e10 1e12 \
  --index-cache --index-cache-format npz \
  --out-dir o7_metastable_coupling \
  --print-summary
\end{lstlisting}

The CSV output reports \texttt{q\_2\_to\_j\_cm3\_s},
\texttt{C\_2\_to\_j\_s\textasciicircum{}-1}, decoded radiative A-values, and density estimates
where collisional transfer becomes comparable to radiative decay.


\section{He-like collisional coupling diagnostics}

Version 0.2.47 adds XSTAR He-like collision decoders for data types 67, 68, and 69.
